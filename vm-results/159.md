# Review 159: AI-written timeline events

**BLOCK 9**

Reviewed `fbf4637` against `c0df9d1` (0.3.0), with `suite-notes/timeline-briefs/J2.md` and the shared timeline specification. The approved artifact URL could not be opened and its local mockup shots were unavailable; the review used the brief and checked-in tests. The following are independent writer-visible paths.

1. **Fixing one draft problem erases another, so an unresolved draft can be kept.** `src/timeline/drafts.js:23-34` attaches all reader notes to one signature of the date, dependency, delay *and* places. On Ersveil, paste `[{"name":"Lost parent","when":{"after":"Missing king","days":3},"where":["Not Here"],"news":"A king dies"}]`, check and add the draft. The banner reports both the missing parent and unknown place, and Keep is disabled. Remove only the `Not Here` place chip. Both warnings disappear and Keep becomes enabled. Keeping it exports `{ "id":"lost-parent", "when":"true", "cue":"A king dies" }`: it can fire immediately, although the missing three-day dependency was never fixed. Reproduced through the actual form using the DOM test harness. Notes need to remain tied to the particular unresolved field, rather than any change to the combined signature.

2. **Malformed constraints silently turn into unrestricted, keepable events.** `src/timeline/ai-answer.js:154-163,258-262,275-277` discards unsupported `where`, `on`, and `until` types instead of recording a problem. Paste `[{"name":"Report","when":{"on":12345},"where":{"name":"Restricted City"},"news":"It happened"}]`. It is marked Ready, its record is `when: "true"`, and Keep succeeds: neither its date nor its location is applied. Likewise `once: "false"` is treated as the default once-only event, and a non-string `until` is ignored. These are ordinary malformed answer fields, not an explicit request for any time/anywhere.

3. **A pasted lasting name can produce an unparseable condition that passes Keep and export validation.** `src/timeline/ai-answer.js:270-271,279` passes a lasting name into the condition writer; `src/timeline/condition.js:22` leaves a carriage return unescaped. Paste the JSON below (the `\r` is the two-character JSON escape), check it, add both drafts and Keep all:

   ```json
   [{"name":"Parent","when":"any time","news":"P","lasting":{"name":"Before\rafter","state":"ongoing"}},{"name":"Child","when":{"after":"Parent","days":1},"news":"C"}]
   ```

   Both are Ready and the resulting pack validation is OK, but Story Block's `parse(child.when)` returns `SYNTAX: A quoted word ... is never closed` because the condition contains a literal CR. The child therefore cannot run as described. This is a new route from the paste reader into the existing writer; checking only the pack validator is insufficient here.

4. **A name collision silently binds an “after” to the wrong event.** `src/timeline/ai-answer.js:222-236` always prefers a pack event to an answer event with the same base name. Start with an event `the-king-dies`, whose lasting change is `Old death`. Paste an answer containing a new `The king dies` with lasting `New death`, followed by `News arrives` with `when: {"after":"The king dies","days":3}`. Studio renames the new parent to `the-king-dies-2`, but the child is Ready with `after: "the-king-dies"` and `chronicle.passed` on `Old death`. It reports no ambiguity on the child and can keep both. The child can thus be triggered by the old event rather than the parent just proposed in the answer.

5. **A draft can become impossible to open, keep, or discard after adding an ordinary event.** `src/screens/timeline.js:17-21,90-92,115-124` generates new IDs using only pack events and resolves a selected ID to a pack event before a draft. Add a draft named `New event`, then click `+ Add event`. Both rows now have `new-event`; clicking the dashed draft row opens the normal pack event inspector, with no draft banner or Discard button. The draft is stranded until the conflicting pack event is renamed or removed. Reproduced through the DOM test harness.

6. **A hostile delay can throw out of Check instead of producing a plain problem.** At `src/timeline/ai-answer.js:269`, an invalid delay is converted with `String(...)` without protection. Paste the following and press Check it:

   ```json
   [{"name":"Parent","news":"P","lasting":{"name":"Parent","state":"ongoing"}},{"name":"Child","when":{"after":"Parent","days":{"toString":null}},"news":"C"}]
   ```

   `readAnswer` throws `TypeError: Cannot convert object to primitive value`. An array nested about 5,000 levels deep in `days` instead throws `RangeError: Maximum call stack size exceeded`. No checked results or plain explanation are produced.

7. **Unbounded pastes can freeze checking and silently defeat project persistence.** `src/timeline/ai-answer.js:55-75,154-163` places no bound on source/field size, and duplicate detection in `where` scans the accumulated list for every item. A single event with 60,000 distinct unknown `where` names (about 1.3 MB JSON) took about 6 seconds synchronously in Node 24 here, before it was rejected as an overlong condition. Separately, an event with a 3 MiB `news` string can be checked and added as a warning draft. `writeDraft` then returns false because its saved payload exceeds 3 MiB (`src/session.js:31-46`), but `src/studio.js:168` ignores that result. Reload restores the previous snapshot without the new draft; subsequent edits also cannot be saved while the oversized draft remains. No save failure is shown.

8. **The prompt can exceed 24,000 characters even for a valid pack.** `src/timeline/ai-prompt.js:103-110,133-153` only budgets the final place list; the calendar, regions, names, events and idea can already exceed the cap. This valid-pack generator reproduced 32,095 characters with all options on and 25,837 with places off:

   ```js
   import { openPack } from './src/model.js';
   import { buildPrompt } from './src/timeline/ai-prompt.js';
   import { writeCondition } from './src/timeline/condition.js';
   const pad = (p, i, n = 75) => `${p}${i} ${String.fromCharCode(65 + i % 26).repeat(n - p.length - String(i).length - 1)}`;
   const places = Array.from({length: 80}, (_, i) => ({slug: `place-${i}`, name: pad('Place', i), region: pad('Region', i), x: 0, y: 0}));
   const creatures = Array.from({length: 100}, (_, i) => ({slug: `npc-${i}`, name: pad('Lore', i)}));
   const events = Array.from({length: 40}, (_, i) => ({id: `event-${i}-${'e'.repeat(48)}`, when: writeCondition({where: places.slice(0, 3).map(p => ({kind: 'place', name: p.name}))}).when, cue: 'News'}));
   const calendar = {era: 'CY', months: Array.from({length: 60}, (_, i) => ({name: pad('Month', i, 38), days: 30})), start: {year: 1, month: 1, day: 1}};
   const model = openPack({id: 'big', version: '1.0.0', name: 'Big', requires: {storyBlock: '^2'}, calendar, content: {places, creatures, events}});
   console.log(model.validation.ok, buildPrompt(model.document, {idea: 'a'.repeat(2000)}).characters);
   console.log(buildPrompt(model.document, {idea: 'a'.repeat(2000), include: {places: false}}).characters);
   ```

9. **Prose containing a citation before the JSON hides the answer.** `src/timeline/ai-answer.js:68-78` stops at the first syntactically valid array, even when it contains no event. Paste `Here is your answer [1]: [{"name":"First","when":"any time","news":"News"}]` without a fence. Check reports no events and skips entry 1; the actual event is never read. Prose around a JSON answer is an explicitly supported input.
