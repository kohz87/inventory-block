## Focus (2): the pack checker now runs on every read of an installed pack

### Where it runs
`src/v2/packs/installed.js` re-validates every stored pack with `validatePack` on read (`check()`, cached per stored object): in `list()` and `packs()`. `packs()` feeds items, start state, currency/economy, calendar, weather, crafts, events, data-module offers, Rank, markets. So the new `when` check is not only the kit checker and install: it also runs every time the settings are read at startup / chat open. A stored pack that fails "stays listed with its problem and gives no content" (installed.js header).

### The behaviour change (old runtime tolerated this)
On 2.11.2 an event whose condition cannot be read is one `invalid` row in the Events debug section (engine.js `normalizeEvents`); the rest of the pack, and the pack's other events, work. On 2.11.3 the same stored pack fails validation as a whole.

### `compile` safety
Side effects: only a module-level cache (500 entries, first-in first-out, keyed on options + source; values, errors included, are deep-frozen). Validating many events can push warm runtime entries out; cost is one re-parse. No Object.prototype change after a run of hostile inputs.
Hostile strings (checked on e1380f8): 10k and 100k-character lines, 100k nested `(`, `!`, `-`, `[0]`, `{a:` all return LIMIT in under 2 ms (1000-character source limit; 200 tokens; depth 24). Inside the limits: 480 nested parens give "more than 200 parts". `.constructor` and record keys `__proto__`/`constructor` are refused at parse (`['__proto__']` parses and is refused when read at play time, as before); `toString`, `hasOwnProperty()` are unknown names. NUL / RTL characters inside a quoted word parse. Non-string, empty, whitespace and 501-character `when` never reach `compile`; a `when` object with a throwing `toString` is refused by the existing data-only check. The validator limit (500) is below the parser's (1000), so no condition valid by length at install can fail the parser on length.
