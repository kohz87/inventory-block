## Blockers in the follow-up

1. **“Right after is fine” accepts an existing two-day delay.** In Ersveil, paste, check, and add:

   ```json
   [{"name":"Parent","news":"P","lasting":{"name":"P changed","state":"ongoing"}},
    {"name":"Child","when":{"after":"Parent","days":2,"hours":null},"news":"C"}]
   ```

   Open the child draft. The banner says the null hours are invalid and offers **Right after is fine**. Click that button and then **Keep all 2 drafts**. The child is saved with `query('chronicle.passed', { name: 'P changed', minutes: 2880 })`: it still waits two days, despite the button the writer pressed. The warning is removed, so there is no further confirmation. The newly checked second unit uses the default delay acknowledgement in `src/timeline/ai-answer.js:419` and `:287`; `ackNote` removes only the note. The two-valid-unit case correctly uses a label naming the retained delay, but the invalid-unit case does not. Cover acknowledgement and the saved condition with a valid unit both before and after an invalid one.

2. **An empty faction is silently removed and the event is marked Ready.** Paste and check:

   ```json
   [{"name":"Harbor crisis","news":"Harbor closes.",
     "lasting":{"name":"Harbor crisis","state":"ongoing",
                "factions":["Ironbound","","Tidecallers"]}}]
   ```

   The card says Ready, with no note. Add and Keep the draft: the lasting payload contains only `Ironbound` and `Tidecallers`. A blank faction is invalid according to `checkLasting` (`src/timeline/lasting.js:35`); on the previous head it remained in the payload and was refused. The new filter at `src/timeline/ai-answer.js:258-259` removes blank or whitespace-only strings but counts only non-strings as unread, so the dropped invalid entry is never said or accepted. The new mixed-faction test includes an empty string but only checks the separate non-string warning, so it does not catch this. Give blank faction entries a warning and acceptance path as for other invalid optional faction entries.

3. **A grouped faction warning can require cutting a valid list and offer no way to accept it.** Paste and add:

   ```json
   [{"name":"Harbor crisis","news":"Harbor closes.",
     "lasting":{"name":"Harbor crisis","state":"ongoing",
                "factions":["North","South","East","West",null,"Harbor"]}}]
   ```

   The payload has exactly the four valid names North, South, East and West. Nevertheless, the banner says the list still needs cutting down, has no accept button, and disables Keep. The writer cannot accept the retained four as they stand, even though that list passes the checker. `src/timeline/ai-answer.js:257-267` bases `cut` on the original six items before removing the invalid entry and suppresses the acknowledgement even when the remaining payload is valid.

   This can also strand a writer who removes the entire lasting change. With the same event and `"factions":[null,null,null,null,null,"Harbor"]`, add the draft and turn off **Add to Story Director's chronicle**. Keep remains disabled by the same unacknowledgeable faction note, even though the lasting change is gone. Its ordinary saved signature is `[null]` both before and after removing the change (`src/timeline/drafts.js:58`), so the warning persists. This is produced by an ordinary pasted answer, not corrupted browser storage. Test both a valid retained list and removal of the change, with an explicit way to resolve the warning.
