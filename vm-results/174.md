## Focus findings

**1. Replay of `~ you` lines and pencils.** I wrote my own fuzz (`youfuzz.mjs`): `~ you` lines (rank/wearing/condition, any parts, empty clears), pencil edits through `scene.you`, new swipe, swipe to an old swipe, regenerate, Re-read of any reply, delete of the last or a middle reply, reload, and (second mode) pack on/off and the feature on/off. After every step: the repo's `checkInvariants` (rebuild == live at every carrier), a fresh host over a copy of the chat has an identical head (reload == live), `validateScene` clean, no throw. Plus Re-read of an unchanged reply must not change the look.
- Mode with pack and feature toggles, 30 seeds x 60 steps: 30 of 30 clean.
- Mode without toggles, 60 seeds x 60 steps, Re-read idempotence on: 60 of 60 clean. (Two harmless things I saw before normalising: a Re-read can add or drop a `rank: ''` key in `scene.you` (reads the same); and `place.kind` changing on Re-read, which also happens on 2.9.4 with the same seeds, so not from this change.)
- Pencil vs Re-read, 40 combinations (reply with or without a line, line edited to another part or another value, a prior reply with a look, a swipe first): the pencil value always survives a Re-read of its own reply, rebuild == live and reload == live in all. A pencil, then a swipe and a swipe back, brings the pencil back; deleting the reply takes it back.
- Old chat (2.10.0 chat with a look opened on 2.9.4): loads with no Problems, accepts new replies, and comes back to 2.10.0 with the look intact. Chats without `you` read empty.

**2. Function-valued grammar.** Every reader goes through `grammarOf` or the registry's `contexts()`: prompt building (`prompt.js`), the Assist extractor (`runtime.js` passes `contexts()` strings; `grammarKind` parses the string), `capture.js` grammar heads, `turn.js`, the registry's own listing, `definitionProblems` (accepts a function). `sdk.modules()` lists kind names only. A function that throws or answers more than one line gives '' and the kind is left out of the listing. The pack list is validated once and cached (`packs.youRank` 0.1 ms with Ersveil installed). The pack checker (`authoring-kit/check.mjs`) imports the same `validatePack`, so it knows `content.you`. I found no caller that assumes a string.

**3. Pack on/off with a stored rank.** Rebuild and reload replay stored ops, so they do not depend on the pack; turning a pack off hides the rank in the query, tail, grammar and Home, keeps the value, and turning it on brings it back (also covered in the repo tests and my toggle fuzz).

**4. Feature off = 2.9.4 prompts.**
- Off-flow fingerprint: running `off-flow.js` on 2.9.4 gives exactly `fixtures/off-2.9.4.json`; on the new branch with `story-block.you` off it gives the identical fingerprint (prompts, draws, receipts); with it on, it equals the new `off-2.10.0.json`. So the regenerated fixture differs only by the feature's lines.
- My own chat (place, weather, items, coin, present, choices, chatter, swipe, regenerate, Re-read, four sends): all request texts byte-identical between 2.9.4 and the new branch with the feature off (`cmp`, 14993 bytes). Same chat with a `~ you wearing … | condition …` line in a reply, feature off: also byte-identical. With the feature on and nothing set, the only difference is the one grammar line; once set, the one tail line.

**5. Validator.** The `content.you` key is added to a normalized pack only when given, so every other example/fixture pack normalizes to the same bytes and the same `packHash` on 2.9.4 and the new code (riverside-starter, tiny-world, ersveil-factions; ersveil-survival is invalid before and after for the same reason). The old Ersveil file still validates; the new Ersveil validates; the new file's normalized form minus `you` equals the old. Ersveil's `packHash` changes because its bytes change, which only affects a fresh `dm.pin` made against an old offer (STALE once, re-inspect); pins keep their own definition and `packHash` and are not compared again.

**6. Text size.** The theme sheet adds only `html:root { --ss-zoom: 0.88|0.96 }` for 110%/120%, nothing for Normal (byte-identical sheet, asserted in tests); the variable is consumed only by `zoom:` on Story Suite's own root classes in `size.css`. No attribute or style goes on any SillyTavern element (test snapshots `<html>` and `<body>`). `textSizeOf` maps unknown/odd values to Normal, and `settings.set` refuses a non-option.

**7. Story Director with an older Story Block.** Real host check (`sd-int.mjs`): with the vendored 2.8.0 testkit (no `scene.you`), `director.status` returns empty rank/wearing/condition, no throw, the card shows nothing new. With 2.10.0: rows come from the reply's state; with the feature off or no rank pack, no Rank row and no throw (the `ask` helper catches). Rank row is shown only with a `rankLabel`.

**8. Hidden values.** The look is {{user}}'s own, so nothing spoiled appears on the Status card or in the tail. Macros the narrator writes in a value (`{{random::…}}`) pass into the tail line as they already do for weather and place; not new.

## Agent's noted edges

(a) A `~ you rank: …` line with no rank-giving pack is refused as a whole, so its wearing and condition are dropped (also when the rank part is empty: `~ you rank: | wearing: hat`). Confirmed. It shows a Problem ("This story has no rank…"), nothing is saved, nothing corrupts, the other lines of the reply are unaffected, and the grammar line does not name rank in that story, so a narrator seldom writes it. It also applies to a Re-read after the pack is turned off. Descriptive state only, so under the bar. Follow-up below.

(b) Pencil value overwritten by a later Re-read line on the same reply: I could not reproduce it. In all 40 combinations the pencil wins over the reply's own lines after a Re-read, and survives swipe and back, reload and rebuild. What does happen, by design as with weather: a later reply's line replaces an earlier reply's pencil value, and a pencil that sets the value the state already has writes no op, so deleting the earlier reply then drops it. Not a blocker.
