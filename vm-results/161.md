Each finding has a writer-visible path.

1. **An unresolved end-date warning disappears when the writer changes only the start mode.** This leaves review 159 B1 open. On Ersveil, paste and check:

   ```json
   [{"name":"Weather report","when":{"on":"Icewane 4, CY 612, dawn"},"until":123,"news":"The storm arrives."}]
   ```

   Add the draft. The banner correctly says the end date should be words and disables Keep. Choose **After another event** under When; leave the **No later than** field empty and do not press **No end date is fine**. The warning disappears and Keep becomes enabled. Keeping produces `{ "id": "weather-report", "when": "true", "cue": "The storm arrives.", "after": "bluewatch-guild-board" }`, with no end bound. Reproduced using the actual inspector with the DOM harness. `src/timeline/drafts.js:37-42,65-70` includes `info.mode` in the `until` note's signature, so changing the start mode clears the note even though the end itself was neither fixed nor explicitly accepted. Both date and after modes support an end. The existing test changes the place and does not exercise this transition.

2. **Present `null` constraint fields silently become defaults.** This leaves B2 open against the lead's explicit rule that a present `once` must be boolean, and that malformed `on`, `until`, `where` and delay fields produce a problem. Paste and check:

   ```json
   [{"name":"Parent","news":"P","lasting":{"name":"P changed","state":"ongoing"}},
    {"name":"Child","when":{"after":"Parent","days":null},"where":null,"once":null,"news":"C"}]
   ```

   Both are Ready and Keep all succeeds. The child is `{ "id": "child", "after": "parent", "when": "true", "cue": "C" }`: its malformed delay, location and repeat setting have silently become right after, anywhere and once. A single event with `"when":{"on":null}` is likewise Ready and keepable as `when: "true"`. `src/timeline/ai-answer.js:194,275,298,340,351,361` treats null as absent; `tests/timeline-ai-answer.test.js:301-310` expressly expects that behavior, contrary to the decision. An omitted optional field can still use the documented default; the issue is a present field of the wrong type.

3. **A failed draft save can be redone into an unsaved project.** This leaves B7 open. Start with a saved project, then make browser storage reject a write containing new drafts, for example because its quota is full. Check an ordinary answer and choose **Add 1 as a draft**. Studio correctly says the drafts were not added and rolls back, but the toolbar **Redo** is enabled. Press it: the draft appears even though saving still fails, while the existing notice continues to say it was not added. Reloading the saved snapshot loses the draft. Reproduced through `mountStudio`, its actual toolbar, and a storage implementation that accepts the previous project but throws on draft writes: after Redo the live model had one draft, `ctx.saved` was false, and the restored model had zero. The rollback at `src/screens/timeline-ai.js:164-174` uses `history.undo()`, which puts the rejected addition on the redo stack; the normal redo handler at `src/studio.js:68-71` does not check the save result. A failed addition also clears any previous redo history. This is distinct from the accepted case where an unavailable store refuses the addition with a plain message: here the refused work can be restored and then lost despite that message.

4. **Two names in one answer that make the same ID can silently bind a child to the wrong parent.** This is a regression in `fbf4637..2b10310`, distinct from B4's pack-versus-answer collision. In a pack without these events, paste:

   ```json
   [{"name":"Dawn-Watch Falls","news":"The fort falls.","lasting":{"name":"Fort falls","state":"ongoing"}},
    {"name":"Dawn Watch Falls","news":"The guard falls.","lasting":{"name":"Guard falls","state":"ongoing"}},
    {"name":"The guard is mourned","when":{"after":"Dawn Watch Falls","days":2},"news":"The guard is mourned."}]
   ```

   All three cards say Ready. The second is renamed `dawn-watch-falls-2`, but the child has no ambiguity note, and Keep all exports it with `after: "dawn-watch-falls"` and `chronicle.passed` on `Fort falls`. It therefore waits for the fort, not the exactly named guard event. Reproduced through the actual check/add/Keep all controls. `src/timeline/ai-answer.js:288-305` now takes the first answer entry for a shared slug rather than resolving the exact answer name or warning about ambiguity. Running the same input against `fbf4637` selected `dawn-watch-falls-2` and `Guard falls`. The accepted capitalization loss in displayed IDs does not account for the wrong event and lasting change.

5. **Valid Unicode in lasting fields is silently cut and kept as if unchanged.** This is a regression in the new field bounding at `src/timeline/ai-answer.js:36,217-231`: `slice` counts UTF-16 code units, but `src/timeline/lasting.js` checks limits in Unicode characters. To reproduce, make a 240-character summary with:

   ```js
   const summary = `${'The southern road remains closed as the city prepares for winter. '.repeat(3)}The council has received warnings. 🐉🐉🐉🐉🐉🐉🐉`;
   const answer = [{ name: 'Road closes', news: 'The road closes.', lasting: { name: 'Road closed', state: 'ongoing', summary } }];
   ```

   Paste `JSON.stringify(answer)`, check, add and Keep. The card says Ready, but the stored summary ends with only four dragons: it has 237 characters rather than the original 240. The same input at `fbf4637` preserves all seven. Over-limit text containing such characters can also be cut below the character limit before validation and produce no warning; a cut can split a surrogate pair. The path was reproduced through the check/add/Keep controls. The same helper bounds the lasting name, place and faction names.
