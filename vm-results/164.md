## Blockers

### B1. Existing unchanged rolls become inactive when loaded at the new head

`side()` adds `pc.statHidden` (`src/v2/lean-rpg/resolve.js:76-82`) for a hidden skill stat or a stat hidden on the Character block. `prepare()` includes that entire `pc` in its replay witness (`resolve.js:166-168`), and `leanRpgGuard()` hashes the new witness against the hash already stored by the parent (`resolve.js:278-290`). Consequently, an unchanged parent roll fails its guard after the update. The changed text of a hidden-resource or hidden-best-stat refusal is likewise part of the witness and produces the same incompatibility.

The real-host repro below stores a normal **attack** with a hidden skill stat at the parent. Its old cue, `Wessel → Rat (Silent Trick)`, never contained the stat, and the parent can load it with its claim present and no problems. Loading the same chat at this head, with no sheet change, reports `REPLAY_PREREQUISITE` / `The sheet before this roll changed; Re-read this reply.` and the `rpg:resolve:<key>` claim is absent from the head. The saved receipt remains queryable; it is the guarded state and claim that are inactive. Re-reading the affected reply repairs this simple example with the same seed and the same summary. A public-stat control stays active at the new head. Existing saved guards need a compatible interpretation or migration; the new visibility metadata and changed refusal wording must not by themselves invalidate unchanged stored rolls.

### B2. Re-reading an existing fight can add an exchange that was never told

The changed check wording also changes its length, and `fitCue()` uses the resulting text length to determine how many combat rounds to keep (`cue.js:43-50,89-104`; `resolve.js:205-225`). A Re-read recomputes that fit from the old plan and seed. Thus the redacted wording can make an additional round fit even though the fight and its saved dice have not changed.

The second real-host case below uses the parent's **normal `dice: 2` payload**, seed 33, four valid checks, one party act and one foe attack. At the parent the cue fits **four** exchanges and stops for `budget`. Parent Re-read preserves four exchanges and the summary. Load the same chat at this head and Re-read: the seed is still 33, but it records **five** exchanges, stops `decisive`, and adds results `cost` and `fail` in round five. This changes a past fight instead of just concealing the stat. The same kind of difference is also possible for the earlier payload without a dice version. This is separate from B1: making the old guard hold does not by itself make a later Re-read preserve the former fitted rounds.

### B3. A missing character stat reveals a skill's hidden stat in a check refusal

The original 163-a successful-check example is fixed, but its hidden choice can still reach the narrator through a check's refusal. `skillFor()` retains and marks the hidden skill stat (`resolve.js:101-108`), but `statOf()` constructs `has no DEX on the sheet` before the visibility flag is passed to `side()` (`resolve.js:125-129,154-162`). If the Character role block has no DEX field, a second valid check ensures the planner's plan is rolled, and the cue says:

`Wessel — Silent Trick: not rolled (Wessel has no DEX on the sheet).`

The planner's skill listing and its Silent Trick plan line do not name DEX. The refusal directly discloses the hidden **skill-to-stat choice**, not merely a total or an allowed outcome such as Down. The second repro below uses actual accepted role blocks, checks both the receipt and actual narrator request, and reproduces it at `f1855b0`. This path also existed at `9f57e18`; it is reported as an incomplete closure of the 163-a hidden-choice rule, not as a regression introduced by this delta. A generic missing-stat refusal can still explain why the check did not roll without naming the hidden choice.

## Reproduce B3 on the requested head

```sh
node --input-type=module <<'JS'
import assert from 'node:assert/strict';
import { createHost } from './testkit/index.js';
import { LEAN_RPG_TEMPLATES } from './src/v2/lean-rpg/templates.js';

  host.features.set('story-block.rpg', true);
```
