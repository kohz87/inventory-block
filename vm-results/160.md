### B1. Hiding a mechanical field (health, soul, foe count) with `prompt: false` changes the rolls, not just the narrator's view (regression of the round-5 B1 fix)
`readSheet` now drops every `prompt:false` field except `alive` (`src/v2/lean-rpg/read.js:73-76`, `:136-141`), but the sheet also drives the rules, not only the text. Dropped values fall back to defaults in `character()` (`read.js:80-92`: `health: int(undefined)=null`, `soul ?? 1`) and in `foesOf` (`read.js:109-117`: hidden count -> 1, hidden class -> 1, hidden hurt -> unhurt). Result: the rules read made-up numbers. `resolve.js:113` refuses a Down actor only on `alive === false || health === 0`; with health hidden it is `null`, so a Down character acts.
Repro (testkit, scripts under scratchpad/review160/scr/hid.test.js and foe.test.js; run `node --test --test-isolation=none` on them):
 a) enable RPG; define Character "Wessel" with `kinds: {}`, `state.health.default = 0`, `state.health.prompt = false`, `state.soul.default = 5`, `state.soul.prompt = false`; define stock Foes with Rat count 1; planner answers `act Wessel | stat: STR | target: Rat`; send a reply. `readSheet` gives `health: null, soul: 1`; the reply records `rpg.resolve` with "Wessel -> Rat: FAIL (9 vs 18)". A character at health 0 (Down) fights, and as Soul class I not V. Before round 5 the Down character was refused.
 b) Foes block with `kinds: {}`, `foe1 = Rat`, `count1.default = 0` (the template says count 0 = empty slot), `count1.prompt = false`. The planner answer `act Wessel | stat: STR | target: Rat` produces "Wessel -> Rat: SUCCESS (27 vs 13)": an empty slot is rolled against (hidden count reads as 1).
Hidden meaning hidden from the narrator (R5 B1) should not make the planner/rules read different numbers. The tests (`round5b.test.js` B1) cover only a hidden foe name, skill name, stat and who. Suggested fix: keep the real value for the rules (health, soul, count, class, hurt) and hide only text sent to the model, or refuse `prompt:false` on those mechanical keys at check time.
